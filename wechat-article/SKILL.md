# 公众号爆款写稿

写公众号成稿，不写运营复盘。用户给主题就直接成稿；缺读者或立场时，用主题推断，不要反复追问。

细则见 [references/templates.md](references/templates.md) 与 [references/compliance.md](references/compliance.md)。

## 写稿前先定 4 件事

1. **结构模板**：用户没指定时，从 10 个模板里直接随机选定 1 个，选定后立刻按它写。不要查时间、不要取模、不要为了“随机”反复试探。模板编号、标题公式、摘要、转发触发器只在内部记住，用来约束这篇怎么写。不要连续默认模板 1。
 2. **标题公式**：再从 10 个标题公式里选 1 个匹配该模板的，见 templates。公众号标题 **13–25 字**（含标点），关键词前置，可用一对括号补利益点。
3. **转发触发器**：先定这一篇靠哪一类被转发——有用 / 认同 / 有面子 / 共鸣。只选一个主触发器。
4. **一篇只讲清一件事。**

推荐偏好（写的时候要能感觉到，不要在文里喊口号）：有真心、有干货、有审美。干货要能照做，观点要有立场，画面要具体。

## 交付格式

### 落盘目录（必须）

每篇成稿单独建一个文件夹，命名为 `时间-文章名`：

```
YYYYMMDD-HHmm-文章名/
├── 文章名.md          # 正文 Markdown
├── 文章名.html        # 默认由 md 转换（用户要求不转时可不生成）
└── images/            # 本篇全部配图
    ├── cover.jpg
    ├── inline-01.jpg
    └── inline-02.jpg
```

规则：

1. **时间**：用完稿时的本地时间，格式 `YYYYMMDD-HHmm`（如 `20261019-1015`）。
2. **文章名**：用标题精简后的短名，去掉特殊符号与空格，可用中文或短横线；过长时截到约 20 字以内。
3. **文章文件**：放在该文件夹根下，扩展名 `.md`；文件名与文章名一致即可。
4. **图片**：一律放在同目录下的 `images/`，不要散落在别处；出图后文件名与占位符 `id` 对齐（如 `cover`、`inline-01`）。
5. 用户指定了输出目录时，在该目录下创建上述文件夹；未指定时，建在当前工作目录。
6. 交稿时在回复里写清最终文件夹路径。

### Markdown → HTML（默认开启）

**默认**在 md 定稿、占位符换成图片相对路径之后，再生成同名 `.html`，与 `.md` 同目录。

- 用户说「不要转 HTML」「只要 md」「跳过 html」等 → **不生成** `.html`。
- 未明确拒绝时 → **必须转换**，不要只交 md。
- 推荐命令（在技能包或项目里执行）：

```bash
python scripts/md_to_html.py "YYYYMMDD-HHmm-文章名/文章名.md"
```

输出默认同目录 `文章名.html`。正文使用行内样式（深绿小标题金边、金句浅底、两端对齐），浏览器打开即可预览。顶部「一键复制」复制的是带样式的正文，可直接粘贴进公众号编辑器。图片路径保持 `images/...`。单独成段的 `**金句**` 或 `>` 引用会渲染成金句条。

### 正文 Markdown

文章 Markdown **不要写 YAML frontmatter**。`title`、`summary`、`template`、`title_formula`、`share_trigger` 只供写稿时自己掌握，不出现在文件里，也不要在正文前用列表交待。

文件从封面占位符开始，接着是 H1 标题：

```markdown
<!-- image-slot
  id: cover
  scene: 文章整体视觉概念
  prompt_hint: 扁平插画，主色与主题相关，封面大字不超过10字
  aspect: 21:9
-->

# 标题

开头 3 行内：场景或痛点 + 这篇能拿走什么。

<!-- image-slot
  id: inline-01
  scene: ...
  prompt_hint: ...
  aspect: 16:9
-->

## 小节标题

正文。金句单独成段，前后空行。
```

出图完成后，把对应占位符替换为相对路径图片引用，例如：

```markdown
![封面](images/cover.jpg)
```

- 内部仍先想好 30–50 字摘要，用来收紧开头，但不要把它写进文件。
- 默认篇幅 **1200–1800 字**（因此必须有封面 + 至少 2 个 inline）。
- 用户明确要短文（<800 字）时，可以只有 cover。

## 图片占位符

写文章时，如果某段内容适合配图，在那段前面插入一个占位符。这样后续出图时能按占位符逐个生成、替换，不用临场决定图放哪。

出图优先级：

1. 用户已有豆包或香蕉生图技能时，按占位符调用对应技能。手帐、拼贴、手绘感用香蕉；写实、扁平商务、封面横幅用豆包。
2. **两者都没有时，用 Agent 自带的生图能力**，按同一条占位符的 `scene`、`prompt_hint`、`aspect` 直接出图，不要因为缺少技能就只留占位符。
3. 生成的图片保存到本篇目录的 `images/`，文件名与占位符 `id` 一致；再回写 Markdown 里的图片相对路径。

### 占位符格式（HTML 注释，Obsidian 可见，公众号渲染时会被过滤）

```
<!-- image-slot
  id: <inline-01 / inline-02 / cover>
  scene: <一句话描述这张图的主题>
  prompt_hint: <给出图工具的视觉建议（可以留空，出图阶段会自动补）>
  aspect: <21:9（封面）/ 16:9（内配图）/ 9:16（竖屏卡片）>
-->
```

### aspect 字段的硬性约定（写稿阶段必须遵守）

| 占位符 id | aspect 必须 | 不允许 |
|---|---|---|
| `cover` | **`21:9`** | 写其他比例 |
| `inline-01 / inline-02 / inline-03` | **`16:9`** | 1:1 / 9:16（除非用户特别要求竖图） |
| 竖屏知识卡 / 朋友圈卡 | `9:16` | — |

aspect 会直接传给配图脚本（`generate_image.py --aspect <值>`）。只写 `21:9`、`16:9`、`9:16` 这三种，不要写成 `21x9`。

**封面**必须有，放在 H1 之前：

```
<!-- image-slot
  id: cover
  scene: 文章整体视觉概念（如"打工人被 AI 工具碎片化"）
  prompt_hint: 扁平商务插画风格，主色紫灰+橙
  aspect: 21:9
-->
```

**内配图**插在对应 H2/H3 **之前**，id 按出现顺序 `inline-01`、`inline-02`、`inline-03`，不跳号。

| 文章字数 | inline 占位符数量 |
|---|---|
| < 800 字 | 可以 0 个 |
| 800–1500 字 | 必须 ≥ 2 个 |
| > 1500 字 | 必须 2–3 个 |

只放 cover、中长文没有 inline，视为没写完。

`prompt_hint` 写画面，不写文章论点，并点明风格。有对应技能时：手帐、拼贴、手绘感交给香蕉，写实、扁平商务、封面横幅交给豆包。没有这两项技能时，同一句 hint 交给 Agent 自带的生图能力。

## 标题规则（公众号）

- 13–25 字。信息前置，3 秒能判断「跟我有关」。
- 优先数字 3 / 5 / 7 / 10；时间周期要可信。
- 括号补充（案例、清单、步骤）可以，不要堆三个卖点。
- 标题必须被正文兑现。朋友圈转发时不要让读者有社交负担（低俗、对老板阴阳、疾病部位直写）。
- 公式与案例见 [references/templates.md](references/templates.md)。

## 正文排版

- 第一人称，对「你」说话。一段不超过 3 行（手机上）。
- 小标题用 `##` / `###`，方便跳读。
- 每个论点：一句判断 → 一个具体细节或步骤 → 一句收束。
- 至少 **3–5 句金句**，各自单独成段：短、有立场、脱离上下文仍成立。用对比、转折或具体名词，不用「很重要」「众所周知」。
- 结尾：一句收回全文 + 一个具体问题邀请评论。不要写「点在看」「转发领资料」「关注抽奖」。

## 写作风格的 6 条原则

### 原则 1：第一人称、说人话

多用"我"、"你"，少用"大家"、"我们"、"各位读者"。一对一对话，不是台上演讲。

### 原则 2：真实经历优先

"我去年做过一次类似的事"比"行业普遍认为"更可信。没亲身做过的事老实说"这是我看到的"，不假装权威。

### 原则 3：观点要敢表达

公众号最忌四平八稳。可以反对、可以提少数派观点、可以下具体判断。但要有理由、不踩人、留余地。

### 原则 4：一篇只讲清一件事

不要在一篇文章里同时塞 3 个主题。

### 原则 5：每段尽量短

一段不超过 3 行。长段落在手机屏幕上是阅读杀手。

### 原则 6：有"我"的细节，没"我"的判断

读者爱看你的真实细节（场景、数据、画面），不爱看纯抒情或纯发牢骚。**情绪用细节带出来，不要直接喊出来。**

没做过的数据、案例、人名不要编。需要数字时用「我看到的公开说法」并避免伪造精确百分比。

## 金句

一篇里至少 3–5 句能被单独截图转发的句子。

- 短，一行能写完最好
- 有判断 / 有立场
- 能脱离上下文独立成立
- 句式有节奏（对偶、排比、转折）

造句：把一段话压成一句；把判断说得更绝对一点；用对比、转折、否定；用具体数字或名词替换抽象词。

## 传播触发器

写之前先定主触发器，全文只服务这一个：

| 触发器 | 转发动机 |
|---|---|
| **有用** | 收藏起来怕忘了（清单、教程、避坑） |
| **认同** | 这篇说出了我心里话（观点、立场、吐槽） |
| **有面子** | 转发显得我懂 / 我有品味（深度、洞察） |
| **共鸣** | 这就是在说我 / 我朋友（情绪、故事） |

## 交稿前自检

- [ ] 已建 `YYYYMMDD-HHmm-文章名/`，正文在文件夹根下，图在 `images/`
- [ ] 内部已选定模板、标题公式和转发触发器，正文按它们写完
- [ ] 标题 13–25 字，且正文兑现
- [ ] 文件里没有 YAML，也没有模板名、公式名、summary、share_trigger
- [ ] cover `aspect: 21:9`；中长文 inline ≥ 2 且为 `16:9`
- [ ] 出图后占位符已换成 `images/<id>.…` 相对路径
- [ ] 默认已生成同名 `.html`；仅当用户明确要求不转时才跳过
- [ ] 3–5 句金句单独成段
- [ ] 没有 [references/compliance.md](references/compliance.md) 里的红线用语和导流
